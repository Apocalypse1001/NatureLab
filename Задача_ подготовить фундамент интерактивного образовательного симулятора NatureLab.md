# Задача: подготовить фундамент интерактивного образовательного симулятора NatureLab

Нужно создать первый технический фундамент приложения для интерактивных физических симуляций.

Главная цель будущего проекта:

Пользователь мышкой редактирует 3D-мир, размещает дома, машины, деревья, меняет рельеф и параметры среды, после чего запускает физическую симуляцию.

Первый будущий модуль — FloodLab / симуляция наводнения.

В дальнейшем архитектура должна позволять добавить:

- реки;
- изменение русла;
- эрозию;
- перенос грунта;
- вулканы;
- лаву;
- оползни;
- другие природные процессы.

На этом этапе НЕ нужно создавать полноценную физику воды.

Нужно сделать качественный, расширяемый фундамент.

---

# 1. Целевая архитектура

Приложение должно иметь следующую структуру:

```text
Windows Application
        │
        ├── Launcher
        │
        ├── Three.js frontend
        │
        ├── Python backend
        │
        ├── NVIDIA Warp
        │
        └── WebSocket communication
```

Предполагаемый принцип работы:

```text
NatureLab.exe
      ↓
запускает Python backend
      ↓
инициализирует NVIDIA Warp/CUDA
      ↓
запускает локальный сервер
      ↓
открывает Three.js UI
      ↓
пользователь редактирует мир
      ↓
Three.js отправляет изменения backend
      ↓
Warp рассчитывает состояние
      ↓
backend возвращает результат
      ↓
Three.js отображает изменения
```

Основная GPU:

**NVIDIA RTX 5090 32 GB**

ОС:

**Windows 11**

# 7. NVIDIA Warp

Подключить NVIDIA Warp.

На старте приложения backend должен:

1. импортировать Warp;
2. выполнить `wp.init()`;
3. определить CUDA device;
4. вывести название GPU;
5. выполнить тестовый Warp kernel.

Сделать простой kernel.

Например:

```text
100 000 точек
position += velocity
```

Это нужно только для проверки:

```text
Three.js
↕
Python
↕
Warp
↕
CUDA
```

# 8. Реальная связь Three.js → Warp

Это критически важно.

Не делать frontend и Warp двумя независимыми demo.

Они должны действительно обмениваться данными.

Например:

Пользователь нажимает:

```text
START SIMULATION
```

Three.js отправляет:

```json
{
  "command": "start_simulation"
}
```

Backend запускает Warp kernel.

Warp изменяет позиции тестовых объектов.

Backend возвращает новые координаты.

Three.js обновляет объекты на сцене.

Это должно реально работать.

# 12. Fixed timestep

Физический backend должен использовать fixed timestep.

Например:

```text

```

Frontend может отображать 60/120 FPS независимо от частоты backend.

Это важно для будущей воспроизводимости физических экспериментов.
